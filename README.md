# Car-Rental AI Assistant (Telegram)

Telegram-бот, що бере на себе **першу лінію** прокату авто: миттєво відповідає на
типові питання, рахує ціну за тарифною сіткою, веде діалог бронювання й кваліфікує
лід — а складне чесно передає живому менеджеру. До нього вбудована **операторська
консоль**: кожен діалог — окрема вкладка, менеджер будь-коли перехоплює розмову, а
бот веде картку клієнта й сигналить, коли потрібна людина.

> Демо/шаблон. Бренд (`AutoRent`), тарифи та FAQ — **ілюстративні sample-дані**
> вигаданої компанії. Реальне розгортання задає свій бренд/дані через `.env` і файли
> даних. Архітектурний підхід — у [docs/plan.md](docs/plan.md).

---

## Навіщо це

Перша лінія прокат-компаній часто **повністю ручна**: бронь = заявка «ім'я + телефон»,
менеджер передзвонює і вручну рахує ціну по таблиці, повторює ті самі відповіді
(застава / документи / пробіг / виїзд за кордон) і губить звернення вночі та в пік.
Бот закриває рутину, лишаючи менеджерам теплі ліди й складні випадки.

## Можливості

**Для клієнта (у Telegram):**
- 💬 Відповіді на типові питання (FAQ) — миттєво, 24/7.
- 💶 Розрахунок ціни за **тарифною сіткою** (sample) (клас × період × застава).
- 🚗 Діалог бронювання зі **слот-філінгом** — бот допитує лише те, чого бракує
  (авто → дати → місто → контакт), уточнює модель, показує ціну й збирає теплий лід.
- 🙋 Чесна передача людині на прохання клієнта чи при скарзі — без «впарювання».

**Для менеджерів (операторська консоль у групі):**
- 🗂 **Окрема вкладка (тема) на кожен діалог** — без спаму в спільний потік.
- 🤫 **Тихе дзеркало**: усі повідомлення дублюються у вкладку беззвучно — для історії.
- 🛑 **Перехоплення/повернення** однією кнопкою: бот замовкає, менеджер веде сам, потім
  повертає боту.
- ✍️ **Підпис і привітання**: перша відповідь людини — «Вітаю, з вами менеджер …»,
  далі підпис. Клієнт завжди знає, бот це чи людина.
- 📌 **Картка клієнта** закріплена зверху вкладки: авто-заповнюється (контакт, інтерес,
  статус «лід») + нотатки команди.
- 📝 **Внутрішні нотатки** `// текст` — лишаються в картці, клієнту не йдуть.
- 🔔 **Тривоги зі згадкою**: коли потрібна людина (лід / бот не зміг / просить менеджера /
  скарга) — гучний пінг, що пробиває mute, з цитатою клієнта.

**Вимірювання:**
- 📊 Кожен хід пишеться в `data/conversations.jsonl` (ML-ready) — видно, скільки бот
  закриває сам, скільки додає LLM, скільки йде людині. `/stats` показує наживо.

## Архітектура — «драбина» rules → LLM → ML

Кожен шар вмикається там, де він **найдешевший і найточніший**. Факти й ціни — це
правила (LLM їх вигадати не може). LLM — лише для розуміння вільної мови. ML —
**пізніше** і лише там, де даними доведено перевагу (див. [docs/plan.md](docs/plan.md)).

```
Клієнт (Telegram)
      │
      ▼
  Розуміння наміру (правила; згодом — ML-класифікатор)
      ├─ FAQ?     → відповідь з бази ПРАВИЛ (0 галюцинацій)
      ├─ Ціна?    → детермінований КАЛЬКУЛЯТОР (тарифна сітка)
      ├─ Бронь?   → слот-філінг → теплий лід
      └─ Складне / прохання людини → LLM або передача оператору
      │
      ▼
  Операторська консоль (Telegram-група як «міст»)
      ├─ вкладка на діалог · перехоплення · підпис · картка клієнта
      └─ тривоги зі згадкою менеджера
      │
      ▼
  Лог кожного ходу → data/conversations.jsonl (фундамент під майбутній ML)
```

## Канал-незалежне ядро (мультиканальність)

Це **не бот суто для Telegram, а переносне ядро автоматизації першої лінії**. Уся
логіка (`pricing`, `faq`, `booking`, `intent`, `dispatch`, `store`, `llm`) **нічого
не знає про Telegram** — про канал знає лише `bot.py`. Доказ: `cli.py` ганяє той самий
`dispatch` у терміналі без Telegram. Тобто Telegram — це **один тонкий адаптер**, а не
весь продукт.

Підключити Viber, WhatsApp, Messenger чи чат на сайті = **написати ще один адаптер**,
без переписування логіки. Кнопки даємо там, де платформа їх підтримує (Telegram —
повні inline-клавіатури; WhatsApp — до 3 кнопок + списки; Viber — клавіатури), а де
UI нема (SMS, email) — працює текст: **правила + LLM + передача менеджеру**. Один
мозок = одна база даних і єдина аналітика по всіх каналах.

## Структура проєкту

```
bot/
  pricing.py    калькулятор ціни (детермінований, кирилиця+токени)
  faq.py        rules-first пошук FAQ (стемінг укр. відмінків)
  booking.py    slot-filling діалог бронювання (+ розпізнавання класів, вихід з броні)
  intent.py     роутер намірів (ціна/FAQ/бронь/ескалація) + класифікатори ДТП/хендофф
  dispatch.py   єдина точка рішення для клієнтського повідомлення (bot + cli)
  llm.py        LLM-ескалація (OpenRouter або локальна модель, із запобіжниками)
  store.py      ML-ready лог діалогів + метрики ефективності
  ops_state.py  стан операторки (режими, теми, картки, привітання)
  config.py     завантаження .env + налаштування
  cli.py        термінальний симулятор чату (без Telegram)
  bot.py        Telegram-обв'язка: хендлери, консоль, тривоги, картки
data/
  tariffs.json  тарифна сітка (sample, вигадана компанія)
  faq.json      база FAQ (sample-дані)
docs/
  plan.md       дорожня карта rules → LLM → ML, фази, ризики, бізнес-розділ
  operator-guide.md  регламент для менеджерів
```

## Швидкий старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # заповни TELEGRAM_BOT_TOKEN (+ опційно решту)
python3 -m bot.bot            # запустити бота в Telegram
```

Без Telegram, прямо в терміналі (rules-only, $0, без ключів):

```bash
python3 -m bot.cli
```

Окремі модулі можна гнати самостійно як демо/тести:

```bash
python3 -m bot.pricing        # приклади розрахунку ціни
python3 -m bot.faq            # приклади пошуку FAQ
python3 -m bot.booking        # приклад діалогу бронювання
python3 -m bot.store          # приклад метрик ефективності
```

## Тести

```bash
pip install -r requirements-dev.txt
python3 -m pytest -q
```

Покрито чисту логіку (без мережі/Telegram): калькулятор ціни, пошук FAQ, діалог
бронювання, маршрутизацію (dispatch), стан операторки (режими/теми/картки), лог метрик +
ML-мітку, класифікатори ДТП/хендофф, мапінг кнопкового меню — 48 тестів. Telegram-хендлери
та реальний виклик LLM перевіряються вручну (інтеграційно), автотестами поки не покриті.

## Налаштування (.env)

| Змінна | Обов'язково | Призначення |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | так | токен бота від @BotFather |
| `OPERATORS_CHAT_ID` | для операторки | ID групи менеджерів (бот — адмін з правами тем і пінів) |
| `MANAGER_IDS` | для тривог | user ID менеджерів для @згадки (через кому) |
| `MANAGER_NAMES` | для підпису | `id=Імʼя` — підпис менеджера для клієнта |
| `COMPANY_PHONE` | для ДТП | реальний телефон для екстрених відповідей (дефолт є) |
| `LLM_BASE_URL` | ні | ендпоінт LLM (OpenRouter за замовч.; локально — Ollama/LM Studio) |
| `LLM_API_KEY` | ні | ключ LLM; вмикає ескалацію (`OPENROUTER_API_KEY` — legacy-аліас) |
| `LLM_MODEL` | ні | модель LLM (дефолт — безкоштовна) |

## Команди бота

| Команда | Де | Що робить |
|---|---|---|
| `/start` | приватний чат | привітання клієнта |
| `/id` | група | показує ID чату (для `OPERATORS_CHAT_ID`) |
| `/whoami` | будь-де | показує твій user ID (для `MANAGER_IDS`) |
| `/stats` | будь-де | метрики ефективності бота *(лише менеджерам з `MANAGER_IDS`)* |

Операторка: у вкладці клієнта — кнопка **🛑 Перехопити / ▶️ Повернути боту**; звичайний
текст іде клієнту з підписом; `// текст` — внутрішня нотатка в картку; `//booked`/`//lost`/
`//wrong` — мітка результату для ML. Лише менеджери з `MANAGER_IDS` можуть перехоплювати й
відповідати. **Повний посібник для менеджерів — [docs/operator-guide.md](docs/operator-guide.md).**

## Дані та приватність

- Реальні діалоги (`data/conversations.jsonl`), стан операторки (`modes/topics/cards.json`)
  і `.env` — **у `.gitignore`**, не комітяться.
- Підпис менеджера береться лише з `MANAGER_NAMES`, ніколи з Telegram-профілю.
- Ціни/FAQ — ілюстративні sample-дані вигаданої компанії.

## Обмеження (чесно)

- **LLM і Telegram-частина** доведені компіляцією та ручним тестом у Telegram; повного
  автотестового покриття Telegram-шляхів немає.
- Без `LLM_API_KEY` (чи локального `LLM_BASE_URL`) бот відповідає лише на відоме (правила), решту віддає людині.
- Розбір дат («на завтра», «до кінця місяця») і скарг — поки по ключах/простих правилах;
  точніше буде з LLM.
- Наявність авто підтверджує менеджер — бот дає **орієнтовну** ціну й збирає лід.
- ML (скоринг лідів, класифікатор намірів) — **майбутня фаза**, вмикається за обсягом
  даних і перевіркою на held-out. Деталі — [docs/plan.md](docs/plan.md).
- Сховище — JSON/JSONL (достатньо на цьому масштабі); під високим конкурентним
  навантаженням варто перейти на SQLite + блокування.

## Для продакшену (чесно про прогалини)

Демо запускається як `python3 -m bot.bot` (long-polling). Для реального деплою треба
докласти: авто-рестарт (systemd / `docker --restart=always`), ротацію логів і
моніторинг «живості», ін'єкцію секретів через оточення (не файл), CI з тестами.
Перед публічним репо — прибрати рантайм-файли з реальними даними (вже у `.gitignore`).

## Стек

Python 3.9+, [python-telegram-bot](https://python-telegram-bot.org/) 21.x. LLM-виклики —
через `urllib` (без SDK). Сховище — JSON/JSONL (без БД, достатньо на цьому масштабі).
